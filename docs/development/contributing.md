# Contributing Guidelines

## Welcome Contributors!

Thank you for your interest in contributing to the NASA AI App project!

## Getting Started

### Before You Begin
1. Read the [Project Overview](../project/overview.md)
2. Set up your [Development Environment](./setup.md)
3. Review the [Coding Standards](./coding-standards.md)

## How to Contribute

### Types of Contributions
We welcome the following types of contributions:
- 🐛 Bug fixes
- ✨ New features
- 📚 Documentation improvements
- 🧪 Test coverage improvements
- 🎨 UI/UX improvements

### Contribution Process

#### 1. Find an Issue
- Browse [open issues](../../issues)
- Look for issues labeled `good first issue` for beginners
- Comment on the issue to claim it

#### 2. Fork and Clone
```bash
# Fork the repository on GitHub
# Then clone your fork
git clone https://github.com/[your-username]/NasaAI.git
cd NasaAI
```

#### 3. Create a Branch
```bash
git checkout -b feature/your-feature-name
# or
git checkout -b bugfix/issue-number
```

#### 4. Make Changes
- Follow the [coding standards](./coding-standards.md)
- Write clear, descriptive commit messages
- Add tests for new functionality
- Update documentation as needed

#### 5. Test Your Changes
```bash
# Run tests
[test command]

# Run linters
[lint command]

# Test manually
[manual test instructions]
```

#### 6. Submit a Pull Request
- Push your branch to your fork
- Create a pull request against the main repository
- Use the pull request template
- Link related issues

## Pull Request Guidelines

### PR Title Format
- Use clear, descriptive titles
- Start with a verb (Add, Fix, Update, Remove)
- Reference issue numbers where applicable

Examples:
- `Add user authentication feature (#123)`
- `Fix memory leak in data processing (#456)`
- `Update API documentation for v2.0`

### PR Description Template
```markdown
## Description
Brief description of changes

## Type of Change
- [ ] Bug fix
- [ ] New feature
- [ ] Documentation update
- [ ] Other (please describe)

## Testing
- [ ] Unit tests pass
- [ ] Integration tests pass
- [ ] Manual testing completed

## Related Issues
Closes #[issue number]

## Screenshots (if applicable)
[Add screenshots for UI changes]
```

## Code Review Process

### Review Criteria
- Code follows project standards
- Tests are included and passing
- Documentation is updated
- No breaking changes (unless intended)
- Performance impact is considered

### Review Timeline
- Initial review within 2-3 business days
- Follow-up reviews within 1-2 business days

## Community Guidelines

### Code of Conduct
- Be respectful and inclusive
- Provide constructive feedback
- Help others learn and grow
- Follow professional communication standards

### Communication Channels
- GitHub Issues: Bug reports and feature requests
- GitHub Discussions: General questions and ideas
- Pull Request Comments: Code-specific discussions

## Recognition

Contributors will be recognized in:
- Project README
- Release notes
- Contributors file

## Questions?

If you have questions:
1. Check existing documentation
2. Search through issues and discussions
3. Create a new issue with the `question` label
